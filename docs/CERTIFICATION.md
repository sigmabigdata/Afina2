# Сертификация и реестр отечественного ПО

## Важно

Требование «все компоненты сертифицированы» **невозможно** в буквальном смысле:
ФСТЭК сертифицирует СЗИ/ОС/СУБД/JDK/веб-серверы, но не UI-библиотеки и не браузеры.
React, Ant Design, Vite и Node не имеют и не могут иметь сертификат ФСТЭК.
Корректная постановка: **сертифицируемое ядро + собственный код**, UI-библиотеки —
общесистемное ПО, не выполняющее защитных функций.

## Реестр отечественного ПО (Минцифры)

- Правообладатель — российская организация, исходники в РФ.
- Продукт должен быть собственной разработкой, не производным foreign ПО.
- Открытые MIT-библиотеки допустимы как компоненты, но требуют юридической оценки.
- Ant Design (Ant Group, Китай) и React (Meta, США) — иностранные open-source;
  для реестра желательно заключение юриста, SBOM и фиксация версий.
- Альтернативы для снижения риска: собственный UI-кит без Ant Design;
  российские UI-библиотеки (например, Consta) — но они тоже не сертифицированы.

## Что подготовить

1. SBOM (CycloneDX) и лицензионный аудит.
2. Перечень компонентов с ролями и обоснованием отсутствия сертификации у UI.
3. Сборка из внутреннего registry, без CDN и внешних вызовов.
4. Матрица соответствия требованиям ФСТЭК/ИБ.
5. Документация: архитектура, модель угроз, инструкции администратора.

## Вывод

Проект можно готовить к реестру и сертификации **ядра**; «сертификат на React»
получить нельзя. Если заказчик требует буквально все компоненты — веб-SPA
невозможен, нужен иной формат поставки.

### Что включено в поставку и проверяется

- **SBOM** (CycloneDX) формируется скриптом `backend/scripts/sbom.sh`:
  Java-зависимости — `cyclonedx-maven-plugin`, npm — `npm sbom`.
- **Лицензионный аудит**: `backend/scripts/licenses.sh` собирает отчёт
  `license-maven-plugin` по всем зависимостям.
- **Статический анализ**: SonarQube (quality gate `afina2`), проект
  `afina2`; покрытие строк ≥ 85 % по бизнес-логике.
- **Тесты**: JUnit 5 + MockMvc (интеграционные, на H2 в режиме PostgreSQL),
  сквозной smoke-тест API `backend/scripts/smoke.sh`.

### Сознательные ограничения

1. **Браузер не сертифицируется.** УКЭП формируется плагином КриптоПро на
   рабочем месте; поддерживаются настольные Chrome/Edge/Firefox/Yandex.
   Мобильные браузеры и Safari не поддерживаются — для мобильной подписи
   предусмотрен «Госключ».
2. **UI-библиотеки не являются СЗИ.** React и Ant Design не выполняют
   защитных функций; они попадают в SBOM и проходят юридическую оценку
   для реестра, но сертификат ФСТЭК на них не запрашивается.
3. **JCSP** поставляется по лицензии правообладателя; ключ лицензии
   задаётся переменной окружения и не хранится в репозитории.
4. **Node.js** используется только на этапе сборки фронтенда и в runtime
   не входит (multi-stage build).

### Что требуется от заказчика для реестра

1. Заключение юриста по иностранным MIT-компонентам (React/AntD).
2. Подтверждение прав на КриптоПро JCSP (лицензионный договор).
3. SBOM и лицензионный отчёт из CI (артефакты сборки).
4. Модель угроз и инструкция администратора (в этом репозитории:
   `docs/ARCHITECTURE.md`, `deploy/README.md`).
